# TimeTrace 1.4.0 代码结构

保持单原生进程、一个工作线程、一秒心跳和五秒批量保存。采集、配置写入和查询由同一队列串行处理，无新增运行时、线程或定时器。

| 职责 | 文件 | 说明 |
|---|---|---|
| 统计采集 | `main.cpp`、`platform.cpp`、`core.cpp` | 前台事件、空闲／会话／电源状态，`Timeline` 统一输出活动区间和中断 |
| 应用识别 | `identity.h`、`identity.cpp`、`platform.cpp` | 本机应用目录与证据匹配，区分原始程序身份和展示应用 |
| 提醒 | `reminder_types.h`、`reminders.cpp`、`service.cpp` | 纯 `ReminderEngine` 在内存判断规则，服务串行协调采集、存储和消息 |
| 存储 | `storage.cpp`、`storage_names.cpp`、`storage_reminders.cpp`、`sqlite_statement.h` | 原始区间、名称分组、schema 7 升级，用时与提醒状态原子提交 |
| Windows 通知 | `notification_protocol.cpp`、`notifications.cpp`、`integration.cpp` | Toast XML、严格 URI／IPC 参数、通知身份及安装注册 |
| 界面 | `ui.cpp`、`ui_statistics.cpp`、`ui_reminders.cpp`、`ui_prompts.cpp` | 原生绘图与输入框；字号和尺寸由 `ui_metrics.h` 统一 |

## 时段与提醒

`Timeline` 使用单调时钟计算时长，本地时间只负责日期归属。空应用 ID 的活动区间只进入设备计时，未识别窗口保留原始身份，用时单独汇总并计入总量。应用分组映射在注册、配置或合并时刷新，不在每秒心跳查询全表。

时间线回调只将按本地日期切分的活动与中断依次放入内存队列，由服务消费。跨日先保存前一天待写用时和提醒状态，再载入新一天数据。写入失败时，尚未消费的活动留在队列，时间线仍只推进一次。后续命令重试消费，避免跨午夜失败后重复累计或遗漏活动。清除历史成功后才清空活动队列并重置时间线。

`ReminderRule` 明确区分 `Device` 与 `App`。设备使用本轮实际时长和下一阈值，应用使用当天分组累计。`ReminderState` 保存日期、下一阈值、已提醒、静默及本次通知标识。设备连续计时仅在内存保留，重启清零，今日静默持久化。

提醒引擎先做只读到期检查，仅有到期项才复制回滚检查点并生成 `ReminderEvent`。服务将待写时段与状态放入同一事务，事务失败时恢复检查点，成功后交给主消息窗口显示。查询界面、五秒保存及重启使用同一份已保存状态去重。只有数据库提交成功后才清空待写数据和脏标记。

## 应用名与主来源

`ResolvedApp` 携带原始来源、识别得到的应用名和识别依据。原始程序 ID 写入 `segments`，来源名称、识别应用名与自定义名称分别保存。窗口应用标识、安装目录与快捷方式先提供应用名，组件还结合具体安装目录、发布者和通用组件特征识别归属。

`apps.resolved_name` 保存识别应用名，`name_key` 去除两端空白并使用 Windows 不变区域规则转为小写。`app_labels` 始终保存各来源自己的自定义名称。显示名称优先采用当前主来源的自定义名称，其次为识别应用名。`regroupNames()` 自动汇总同名分类，继续使用既有的展平映射进行查询。自动合并优先保留已有用时、自定义名称及手动成员的主来源，其余按来源 ID 确定顺序。

分类目录只返回有实际使用记录的项目。未知来源通过 `identified` 标记，快照的 `unidentified` 单独汇总这部分用时，趋势和总时长包含它。正数但不足一秒的用时保留并显示“不足1秒”。

启动时完整回放来源元数据，已有手动归属和独立选择保留。新同名来源可通过已有成员识别出改名后的分类。元数据缓存、来源清单和图标读取复用现有工作线程。所有名称整理只发生在迁移、元数据注册或明确配置操作中。每秒心跳继续使用内存映射。

重命名只写入当前主来源。更换主来源调整整组映射及原有提醒的应用绑定，每个来源的名称独立保留。同名重命名及主来源切换需要确认合计用时，存储层也验证确认状态。移出当前主来源需先更换主来源。更改归属在单个事务中移出来源并转入目标，按用时换算两侧剩余延后，作废过期通知标识。独立应用需有不同的分类名称。

服务在上述操作前保存待写用时及提醒状态，完成后重载映射和提醒。元数据登记部分成功后遇到临时写入错误，后续命令先重载已提交映射，再处理剩余登记与活动。原始区间保持原始来源 ID。

## 查询、缓存与资源

尚未执行的界面查询只保留最新请求，采集及配置命令完整保留。快照携带请求序号，界面忽略过期结果与关闭窗口后的结果。关闭窗口释放整个快照、绘图缓存及工作线程的图标缓存；退出时先关闭界面，再停止服务。

应用目录按需读取并缓存，元数据、名称、分组或首次产生用时后失效，提醒与界面查询共用这份目录。`hasUsage` 标记应用是否真正产生过记录，用于筛选合并候选。排行只查询所选时段累计大于零的应用，提醒配置仍独立保留。正数但不足一秒的记录显示“不足1秒”，不将其删去或四舍五入为零。

快照的 `selected` 独立提供当前详情应用的名称、路径与用时。历史日期没有该应用记录时仍能绘制详情。合并界面选择来源项目并入当前应用，服务继续使用明确的 `source → target` 参数，当前应用为目标。

合并候选仅在用户打开合并窗口时，由工作线程使用已有目录索引排序。同目录信息只辅助人工选择，确认后多项来源在一个事务内合并。原生列表显示应用名称与所选时段用时，支持名称搜索、复选框及合并用时预览。程序路径仅在来源管理中展示。

详情快照的 `members` 提供主应用和各原始来源的所选时段用时。固定成员栏及管理窗口支持移出来源、调整主应用。移出只删除归属映射，保留原始区间，按移出来源的用时换算组提醒的剩余延后，并作废旧通知标识。调整主应用切换显示名称和图标来源，同时迁移同一提醒规则，组总量及通知状态保留。服务在这些操作前保存待写数据，完成后重新载入提醒与映射。

应用图标仅在视图查询中提取，由界面请求当前需要的项目，最多缓存 64 项，优先保留详情项。失败结果也缓存，移出当前视图后单项释放。进程解析缓存使用唯一所有权，复用前检查进程存活，避免 PID 重用误归属。托盘使用 `NIF_SHOWTIP` 显示名称及暂停状态，兼容版本 4 托盘消息。

批量写入在事务内复用预编译语句，事务作用域退出自动回滚，绑定错误会作为保存失败处理。周趋势直接按天聚合。版本只在 `CMakeLists.txt` 定义，由生成头文件、资源编译和打包脚本共用。SQLite 保留 WAL、外键与事务，去掉未使用的 JSON、UTF-16、共享缓存和弃用接口。

## 动作与兼容

通知正文使用 `timetrace://reminders`。两个按钮使用 `action=snooze|mute&rule=正整数&token=本次标识`，仅允许有限长度 ASCII 参数，拒绝重复或额外键、非法字符和溢出。协议安装注册保留完整的 `%1` 参数。

新启动进程通过固定版本与长度的 `WM_COPYDATA` 转交既有实例，规则 ID、日期与标识在引擎中再次验证。执行一次即消耗标识，被新通知替代、跨日、规则删除或设备会话结束后失效。没有已有实例时，应用提醒状态恢复后直接执行动作并留在托盘。设备重新启动是一轮新会话，旧设备通知不再有效。

旧限额命令行、旧正文链接和旧预览参数作为入口别名保留，运行逻辑使用新的提醒类型，不复用旧字段。

## schema 7

新数据库直接建立当前七张业务表。`apps.has_usage` 记录应用是否产生过用时，`app_links.manual` 区分自动识别与用户手动合并。schema 4 升级添加这两个字段，根据现有区间推导用时标记，旧分组视为手动分组，并将未受用户设置保护的未知项归到统一展示应用。原始区间、自定义名称、提醒状态及通知标识保留。

schema 5 升级添加 `apps.separate_from`。非空值记录用户主动移出的原组，自动归组尊重该独立选择。再次手动合并会清除旧的移出标记。移出重试按当前归属和原组验证，调整主应用后仍可识别同组操作。新增字段和版本更新在同一事务内完成。

schema 6 升级添加 `resolved_name`、`name_key` 和 `identified`，从原名称和已有自动归属初始化识别名，再汇总同名分类。来源名称、自定义名称、手动成员及原始区间保留。分类合并时沿用目标提醒优先级并换算剩余延后。

schema 3 同时移除废弃的 `limits` 和 `notices`。schema 1／2 首次升级时把旧限额与状态转为提醒，再移除旧表。升级在同一事务内完成，更新版本后启动时直接读取当前表。高于当前版本或损坏的数据文件会报错，避免误清空。

手动合并在同一事务中保留目标规则优先级，按合计用时换算剩余延后时长、继承静默并作废旧通知标识，同时将组内映射展平。原始区间不重写。清除历史在删除事务成功后才重置内存计时和用时标记，保留规则、名称、分组，空间压缩失败不影响已完成的删除。
